## 3. TECHNICAL ARCHITECTURE & PROJECT STRUCTURE

### Directory structure
```
vku-survey/
├─ public/
│  ├─ manifest.json            # PWA manifest
│  └─ icons/                   # 192, 512, maskable 512
├─ src/
│  ├─ main.jsx                 # entry, font imports, SW registration, cloud seeding
│  ├─ App.jsx                  # shell: header, network badge, tabs, toast, sync triggers
│  ├─ sw.js                    # Service Worker (precache + Background Sync)
│  ├─ db.js                    # Dexie schema: surveys, drafts, cloud
│  ├─ cloud.js                 # simulated backend (save, login, list, seed)
│  ├─ sync.js                  # Sequential Sync Engine
│  ├─ lib.js                   # constants, camera, GPS, image resize, CSV
│  ├─ styles.css               # VKU theme (V red, K blue, U yellow)
│  └─ components/
│     ├─ Survey.jsx            # 3-step form + draft persistence
│     ├─ Records.jsx           # local reports with sync status badges
│     └─ Admin.jsx             # login, statistics, CSV export
├─ android/                    # Capacitor Android project
├─ capacitor.config.json       # webDir: dist
├─ wrangler.jsonc              # Cloudflare static assets deploy
└─ vite.config.js              # Vite + vite-plugin-pwa (injectManifest)
```

### Data & state flow
```
Form input ──(every change)──▶ IndexedDB.drafts           (survives refresh)
Save ──▶ IndexedDB.surveys  { id: UUIDv4, createdAt, status: PENDING_SYNC }
                │
  online event / @capacitor/network / Background Sync / "Gửi tất cả"
                ▼
        Sequential Sync Engine (mutex, one report at a time)
        PENDING_SYNC ─▶ SYNCING ─▶ cloud.add(id) ─▶ SYNCED
                                       └─ ConstraintError (same UUID) ─▶ treated as duplicate
                ▼
        IndexedDB.cloud ──▶ Admin dashboard / CSV
```
UI state is local React state; lists use `useLiveQuery` (dexie-react-hooks), so badges update in real time as the engine changes statuses.

### Backend note
No server is required. The "server" is a second IndexedDB store (`cloud`) in `cloud.js`, with simulated latency, UUID-keyed idempotent writes and an in-app admin login. It was designed so that only `cloudSave` and `cloudList` need to be replaced by `fetch()` calls (for example to a Cloudflare Worker + D1) to make the data shared across devices. In the current build, data is per device/browser.

### Exception handling
* **Network loss mid-sync:** the engine stops at the first failure, returns the report to `PENDING_SYNC`, and keeps the queue intact.
* **App killed while `SYNCING`:** `recoverStuck()` resets such records to `PENDING_SYNC` on startup.
* **Double submission:** an in-flight mutex plus the UUID primary key.
* **GPS or camera denied/unavailable:** friendly message, retry button; the report can still be saved without GPS.
* **Storage:** photos are compressed before saving; all IndexedDB writes are awaited before showing success.

## 5. TECHNICAL CHALLENGES & RESOLUTIONS

**1. Booting offline with Vite's hashed assets.**
A hand-written Service Worker that caches files "on first fetch" fails on the very first visit, because the page's own JS/CSS were loaded *before* the SW was active, so the cache is incomplete and the offline boot breaks. *Resolution:* switch `vite-plugin-pwa` to `injectManifest` mode and use Workbox `precacheAndRoute(self.__WB_MANIFEST)`. The build injects the exact list of hashed files (HTML, JS, CSS, WOFF2, icons) into the SW at install time, giving a true Cache-First App Shell. Fonts were moved from a CDN to `@fontsource` packages so they are part of the precache too.

**2. Reliable sync without duplicates.**
Reconnecting can fire `online`, the Capacitor network event and a Background Sync event almost together, and users may also tap *Gửi tất cả* repeatedly, which would send the same report several times. *Resolution:* (a) a single in-flight lock in `syncAll()`; (b) status transitions `PENDING_SYNC → SYNCING → SYNCED` persisted in IndexedDB; (c) the UUIDv4 as primary key on the receiving store, so a repeated write raises `ConstraintError` and is treated as "already received"; (d) `recoverStuck()` on launch for records left in `SYNCING` by a crash.
*Known limitation:* Background Sync in the SW only messages an open window to flush the queue; syncing while the app is fully closed would require moving the Dexie queue logic into the Service Worker.

## 6. HOW TO RUN

```bash
npm install
npm run dev                         # development
npm run build && npm run preview    # test the PWA / Service Worker
```
**Deploy to Cloudflare:** `npm run build && npx wrangler deploy`

**Build the Android APK:**
```bash
npm run build
npx cap add android      # first time only
npx cap sync android
cd android && ./gradlew assembleDebug     # Windows: .\gradlew.bat assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
```
After each code change: `npm run cap:sync`, then rebuild the APK.

**Demo script:** open the app → note the green ONLINE badge → switch to airplane mode (amber OFFLINE) → quick-pick *Khu V · Tầng 1 · V.101* → take a photo → check the GPS card → **Lưu biên bản** (CHỜ GỬI) → turn the network back on → watch ĐANG GỬI → ĐÃ GỬI MÁY CHỦ → tap **Gửi tất cả** repeatedly (no duplicates) → log in as admin and export CSV.
